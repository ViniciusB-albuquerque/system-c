Análise da Execução da Solução Serial

Executando a solução serial em Python e C com diferentes quantidades de turmas e alunos, observei o seguinte comportamento.

1. ORDEM DE EXECUÇÃO
   - A execução é estritamente sequencial, seguindo a ordem dos IDs das turmas
   - Primeiro processa completamente a turma 1 (todos os alunos), depois a turma 2, e assim sucessivamente
   - Não há variação na ordem entre diferentes execuções, o resultado é determinístico

2. PADRÃO DE SAÍDA
   - Professor começa a corrigir turma X
   - Corrige aluno por aluno em ordem sequencial
   - Termina a turma completamente
   - Só então inicia a próxima turma

3. COMPARAÇÃO ENTRE EXECUÇÕES
   - Não houve alteração na ordem de execução entre diferentes execuções
   - O que muda é apenas os valores aleatórios das notas geradas
   - O tempo total pode variar ligeiramente devido aos sleeps aleatórios, rodando com 3 turmas e 3 alunos deu 7,5s e 8,4s no Python e 7,1s no C

4. EXEMPLO DE SAÍDA
   ======================= Welcome to 2025.2's UFCG Semester =======================
   Prof1's class (1) — starting grading...
   Prof1 corrected Student 1 from class 1 - Grade: 1.84
   Prof1 corrected Student 2 from class 1 - Grade: 0.15
   Prof1 corrected Student 3 from class 1 - Grade: 0.88
   Prof1's class 1 grades successfully processed!

   Prof2's class (2) — starting grading...
   Prof2 corrected Student 4 from class 2 - Grade: 4.63
   Prof2 corrected Student 5 from class 2 - Grade: 4.94
   Prof2 corrected Student 6 from class 2 - Grade: 3.60
   Prof2's class 2 grades successfully processed!

5. CONCLUSÃO
   A solução serial executa de maneira previsível e determinística,
   sem intercalação entre as correções das diferentes turmas.
   Isso é ineficiente quando há múltiplos professores disponíveis,
   pois enquanto um professor trabalha, os outros ficam ociosos.
